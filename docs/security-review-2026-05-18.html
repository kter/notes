Critical devバイパストークンが本番DSQLデータベースへアクセス可能 app/auth/cognito.py:73-98, app/auth/app_user_service.py:73-81 ▶

"dev-integration-test-token"、"dev-integration-test-token-2"、"local-dev-token" という平文トークンがリポジトリにコミットされており、environment == "dev" 時に署名検証なしで認証される。さらに sub が "integration-test-user-id" で始まるユーザーには自動的に admin=True が付与される。devは本番DSQLクラスターを共用するため、これらのトークンを知っているユーザーが本番データに管理者権限でアクセス可能。

推奨対応
バイパスを environment == "local" のみに制限、またはdev/本番でDSQLクラスターを分離。バイパストークンをコミットせず、環境変数 DEV_BYPASS_SECRET で管理。
High APIキーをソルトなしSHA-256でハッシュ化 app/auth/api_key_service.py:119-121 ▶

生の hashlib.sha256 でAPIキーを保存。作業因子もソルトもないためGPUブルートフォースに脆弱。テーブル流出時にレインボーテーブルで高速復元される。

推奨対応
HMAC-SHA256（サーバーサイド秘密鍵使用）、bcrypt、またはargon2に変更。最低限ランダムソルトを追加。
High JWTエラー詳細がAPIレスポンスに露出 app/auth/dependencies.py:63-66 ▶

JWT検証失敗時に detail=str(exc) でライブラリ内部のエラーメッセージがそのままHTTP 401レスポンスに含まれる。JWT検証パイプラインの内部情報がトークン偽造攻撃の手がかりになる。

推奨対応
エラーメッセージを "Invalid or expired token" に統一。元の例外はサーバーサイドでのみログ記録。
High 画像アップロード: Content-Typeヘッダーのみ検証 (マジックバイト未確認) app/features/images/use_cases.py:38-41 ▶

クライアントが制御できる file.content_type のみで画像ファイルを検証。HTMLやSVG（埋め込みスクリプト付き）を image/png と偽ってアップロードし、CDN経由で配信させることで格納型XSSが可能。

推奨対応
python-magic でマジックバイト検証を追加。CDNでは Content-Disposition: attachment またはContent-Type強制を設定。
High Bedrock history フィールドへのロールインジェクション app/features/assistant/schemas.py:42, gateway.py:192-200 ▶

ChatRequest.history は list[dict] | None 型で無検証のままBedrockのmessagesに渡される。悪意あるクライアントが {"role": "assistant", ...} を注入して会話履歴を操作し、AIの動作を変えたり他ユーザーのノートコンテキストを引き出せる可能性がある。

推奨対応
role: Literal["user", "assistant"] と最大長制限を持つ型付き ChatHistoryItem Pydanticモデルを定義。
High CORS: 全メソッド・全ヘッダーを認証情報付きで許可 app/main.py:69-75 ▶

allow_methods=["*"] と allow_headers=["*"] を allow_credentials=True と組み合わせることで、許可オリジンからのDELETE/PUT/PATCHを含む全メソッドと全カスタムヘッダーがクッキー・認証トークン付きで送信可能になる。

推奨対応
実際に使用するHTTPメソッドのみを列挙。allow_headers を ["Authorization", "Content-Type", "X-API-Key", "X-Request-ID"] に制限。
Medium 認証・AIエンドポイントにレート制限なし app/main.py (ミドルウェアなし), app/features/assistant/router.py ▶

レート制限ミドルウェアが存在しない。有効なトークンを持つ攻撃者がAIエンドポイントを連打することで、月次カウンターが更新される前に大量のBedrockコストを発生させられる。

推奨対応
API GatewayレベルでのWAFスロットリング、またはSlowAPIミドルウェアによるIP/ユーザーごとのレート制限を追加。
Medium DomainError.detail が 500レスポンスに露出するフォールバック app/http_errors.py:42-45 ▶

未処理の DomainError サブクラスは detail=error.detail がそのままクライアントへ返される。将来追加されたエラーが内部実装情報（テーブル名、クエリ等）を含む場合に情報漏洩となる。

推奨対応
フォールバックを detail="An unexpected error occurred" に変更し、詳細はサーバーサイドでのみERRORレベルでログ記録。
Medium 管理者検索クエリに max_length 制限なし app/features/admin/router.py:36, use_cases.py:55-63 ▶

検索パラメータ q に min_length=1 はあるが max_length がない。100KBの文字列が LIKE '%...%' クエリとして送られるとDB CPUに不必要な負荷がかかる。

推奨対応
max_length=200 (または適切な値) を追加。
Low JWKS キャッシュに TTL なし app/auth/cognito.py:33-43 ▶

JWKSレスポンスがインスタンス変数に永続キャッシュされる。Cognitoが署名鍵をローテーションした場合、ウォームLambdaコンテナで認証が長時間失敗する可能性がある。

推奨対応
24時間TTLを追加、または kid が見つからない場合に再フェッチするフォールバックを実装。

3. フロントエンドアプリケーション脆弱性

🌐 Next.js App Router (frontend/src/)
1C 4H 2M
Critical ReDoS — ユーザー入力を直接 RegExp コンストラクタに渡す components/layout/NoteList.tsx:118 ▶

new RegExp(`(${highlight})`, "gi") で検索クエリをエスケープなしでそのまま使用。ユーザーが ( を入力すると SyntaxError でノートリストが空白になる。(((((((a+)+)+)+)+)+ のようなパターンでブラウザタブがフリーズする（Catastrophic Backtracking）。

推奨対応
highlight.replace(/[.*+?^${}()|[\]\\]/g, '\\$&') でエスケープしてから RegExp に渡す。
High セキュリティHTTPヘッダー未設定 (CSP, X-Frame-Options 等) next.config.ts (headers()エクスポートなし) ▶

CSP、X-Frame-Options、X-Content-Type-Options、HSTS等のセキュリティヘッダーが全て未設定。静的エクスポートのためNext.jsレベルでは設定できないが、CloudFront/S3レベルでも設定されていない（インフラセクション M-3参照）。

推奨対応
CloudFront Response Headers Policyにセキュリティヘッダーを追加。最低限HSTS、X-Content-Type-Options: nosniff、X-Frame-Options: DENYを設定。
High devバイパストークンがクライアントバンドルに平文で含まれる src/lib/dev-bypass.ts:7-17 ▶

BYPASS_TOKEN = "local-dev-token" がビルド時にJSバンドルに焼き込まれる。ステージング環境を検査することでトークン値が判明し、バックエンドが適切に検証しない場合に認証バイパスが成立する。

推奨対応
トークン値をソースコードにハードコードしない。NEXT_PUBLIC_DEV_BYPASS_TOKEN=... 環境変数から読み込む形に変更。バックエンドはインターネット公開環境でバイパスを完全拒否。
High exportNotes で token が null の場合に "Bearer null" を送信 src/lib/api.ts:317 ▶

Authorization: `Bearer ${this.token}` にnullガードがなく、未認証状態で Authorization: Bearer null という文字列リテラルがサーバーに送信される。他のメソッドは正しくガードしているが、このメソッドだけ漏れている。

推奨対応
request() と同様の条件付きヘッダー設定パターンを適用。
High Sentry Replay でレンダリングされたノートコンテンツが記録される可能性 src/lib/sentry.ts:55-59 ▶

replaysOnErrorSampleRate: 1.0 によりエラー時のセッションが100%記録される。maskAllText: true はフォーム入力をマスクするが、プレビューペインに表示されたMarkdownレンダリング済みコンテンツ（prose div）はマスク対象外の可能性がある。

推奨対応
エディタプレビューコンテナをSentryの block リストに追加するか、マスキング設定が全コンテンツ領域をカバーしていることを確認。
Medium 位置情報をサードパーティAPIに同意なく送信 src/components/WeatherWidget.tsx:89-91 ▶

ブラウザの位置情報APIで取得した緯度・経度を直接 api.open-meteo.com のURLクエリに埋め込んで送信。GDPR等のプライバシー規制ではサードパーティへの位置情報共有に明示的な開示が必要。

推奨対応
位置情報取得前に「天気取得のためOpen-Meteoに位置情報が送信されます」という開示を追加。
Medium 管理者ページにミドルウェアレベルの認証ガードなし src/app/admin/page.tsx, src/components/admin/AdminConsole.tsx ▶

静的エクスポートのため /admin のHTML+JSが未認証ユーザーにも配信される。middleware.ts が存在しない。バックエンドAPIは正しく認証を要求するが、管理画面の構造が露出する。

推奨対応
middleware.ts で未認証ユーザーを /admin からリダイレクト、またはサブドメイン + ネットワークレベルアクセス制御を導入。

Critical Cognito MFA 無効 terraform/cognito.tf — mfa_configuration = "OFF" ▶

本番ユーザープールでMFAが完全無効。クレデンシャルスタッフィングやフィッシングでアカウントが即座に乗っ取られる。補完的な制御（適応型認証、IP制限等）も存在しない。

推奨対応

3バケット全てに aws_s3_bucket_server_side_encryption_configuration が設定されていない。AWSデフォルト暗号化は有効だがKMS CMKではなくSSE-S3（AWS管理鍵）。policies/security/s3.rego のOPAポリシーは warn のみで強制されていない。ユーザーアップロード画像バケットでは特にコンプライアンス上の問題となる。

推奨対応
各バケットに明示的なSSE設定を追加。images/cacheバケットはKMS CMKを使用。OPAポリシーの warn を deny に昇格。
High API Gateway: スロットリング・WAF 未設定 terraform/lambda.tf:161-183 — aws_apigatewayv2_stage.default ▶

デフォルトステージに throttling_burst_limit / throttling_rate_limit の設定なし。WAF WebACLの関連付けもない。DDoS攻撃と予期しないLambda実行コストに対して無防備。

推奨対応
default_route_settings にスロットリングを追加。AWS WAF WebACL (AWSManagedRulesCommonRuleSet, AWSManagedRulesKnownBadInputsRuleSet) を関連付け。
High API Gateway: JWT オーソライザーなし (認証をLambda内のみで実施) terraform/lambda.tf:154-158 — aws_apigatewayv2_route.default ▶

キャッチオール $default ルートに authorization_type が設定されていない。未認証リクエストもLambdaが起動してコスト・レイテンシが発生してから拒否される。

推奨対応
CognitoをissuerとするJWTオーソライザーを追加。パブリックエンドポイント（/auth/*）のみ明示的に NONE に設定。
High ECR イメージタグがミュータブル terraform/lambda.tf:111 — image_tag_mutability = "MUTABLE" ▶

latest タグが上書き可能なため、サプライチェーン攻撃や誤ったプッシュで本番Lambdaイメージが静かに置き換わる。タグレベルの監査証跡がない。

推奨対応
image_tag_mutability = "IMMUTABLE" に設定。本番はダイジェスト参照 (@sha256:...) でデプロイ。
High IAM: Lambdaランタイムロールに aws-marketplace:Subscribe 付与 terraform/iam.tf:48-57 — aws_iam_role_policy.bedrock_access ▶

Bedrockアクセスポリシーが aws-marketplace:Subscribe を Resource: "*" で付与。Lambdaが侵害された場合、有料Marketplace製品への購読で多額の課金が発生しうる。ブートストラップ用の権限が常時ランタイムロールに残っている。

推奨対応
ランタイムロールから aws-marketplace:Subscribe を削除。初回モデル購読はコンソールまたはデプロイ専用の権限昇格ロールで実施。
High IAM: CloudWatch Logs リソース ARN がワイルドカード terraform/iam.tf:98, cost_report.tf:87 ▶

Resource = "arn:aws:logs:*:*:*" により任意リージョン・任意アカウントの全ロググループへの書き込みが可能。侵害されたLambdaが他サービスのログを改ざんして監査証跡を汚染できる。

推奨対応
特定のロググループARNパターン (arn:aws:logs:{region}:{account}:log-group:/aws/lambda/{project}-*) に制限。
High SES: 任意の検証済みアイデンティティからの送信を許可 terraform/cost_report.tf:57-69 — ses:SendEmail Resource: "*" ▶

コストレポートLambdaが任意のSES検証済みアイデンティティからメール送信可能。侵害された場合、自社の検証済みドメインを使ったフィッシングメールの送信に悪用されうる。

推奨対応
リソースを特定のSESアイデンティティARN (arn:aws:ses:{region}:{account}:identity/{domain}) に限定。
High SNS/SQS: 保存時暗号化なし terraform/async_jobs.tf — SNS topic, SQS queues ▶

AIジョブのペイロード（ユーザーノートコンテンツを含む可能性）がSNS/SQSに暗号化なしで保存される。DLQは最大14日間メッセージを保持。

推奨対応
SQSに kms_master_key_id = "alias/aws/sqs"、SNSに kms_master_key_id = "alias/aws/sns" を設定。
Medium CloudFront: セキュリティレスポンスヘッダーポリシー未設定 terraform/s3_cloudfront.tf — aws_cloudfront_distribution.main ▶

全キャッシュビヘイビアに response_headers_policy_id なし。HSTS、X-Content-Type-Options、X-Frame-Options、CSP、Referrer-Policy が未設定。初回訪問時のダウングレード攻撃が可能。

推奨対応
aws_cloudfront_response_headers_policy リソースを作成し、全キャッシュビヘイビアに適用。
Medium S3 バージョニング未設定 (images, frontend) terraform/s3_images.tf, s3_cloudfront.tf ▶

imagesバケットでバージョニングがないため誤削除・上書き時に復元不可。frontendバケットも同様。

推奨対応
